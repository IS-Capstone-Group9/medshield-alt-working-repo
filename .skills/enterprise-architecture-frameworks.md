# Enterprise Architecture Frameworks

## Description
Provides the enterprise architecture framing used when MedShield needs to be reviewed at the business, application, data, and technology levels. These frameworks are not required for every task; they become useful when the team needs to explain how the system supports the business and how change should move through the layers. For the capstone, they help show that the solution was designed with business goals, application boundaries, and data structures in mind.

## Workflow
1. Map the business capability or concern first.
2. Review the application, data, and technology layers that support it.
3. Identify gaps, duplication, and dependency risks.
4. Produce the architecture artifact that is useful for the decision at hand.
5. Record the transition path if the current state needs to evolve.
6. Keep the artifact simple enough to explain in the paper.

## Rules
- Use Zachman, TOGAF, or ArchiMate only when they improve clarity.
- Review business, application, data, and technology layers together.
- Keep deliverables grounded in the actual repo and project scope.
- Avoid making the architecture more complex than the problem requires.
- Document target-state and transition-state views when needed.
- Use the framework to clarify decisions, not to slow them down.
- Keep the viewpoint aligned with the capstone story and the actual implementation.

## Deliverables
- Capability maps
- Process maps
- System context diagrams
- Data flow diagrams
- Layer review notes
