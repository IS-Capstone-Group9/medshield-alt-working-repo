# Business Analysis Frameworks

## Description
Provides the business analysis methods used to shape MedShield requirements, scope, process understanding, prioritization, and risk analysis. Choose a framework because it helps answer a question clearly, not because it looks complete on paper. For the capstone, this file should help move from “the system should do analytics” to a concrete business case, user need, and measurable outcome.

## Workflow
1. Clarify the problem, the stakeholders, and the expected business outcome.
2. Choose the framework that fits the question instead of forcing one method everywhere.
3. Turn the analysis into implementable requirements, stories, or decisions.
4. Validate the result with the project goals and constraints.
5. Document assumptions and unresolved questions.
6. Make sure the result can be used directly in the capstone paper or implementation plan.

## Rules
- Use user stories, use cases, and acceptance criteria for requirement definition.
- Use SWOT, PESTLE, root cause analysis, or gap analysis when evaluating business context.
- Use BPMN, SIPOC, or value stream mapping when the process needs to be understood.
- Use decision trees or cost-benefit analysis when a choice needs to be justified.
- Use the power-interest matrix to reason about stakeholders.
- Use risk matrices for risk prioritization.
- Use MoSCoW or Kano when prioritizing requirements.
- Keep the output practical enough that engineering and QA can use it directly.
- Keep the analysis connected to the capstone’s business scope.

## Project Use
- Keep requirements tied to MedShield business value.
- Prefer simple, testable outputs that the delivery team can use immediately.
- Do not over-model when the problem only needs a clear story and acceptance criteria.
